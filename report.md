# Лабораторная работа №1. Скрытый канал на основе изменения длин пакетов

## Вариант 3 — Пример 5 (с параметром n)

**Модель передачи:** Модель 3 — пакеты случайной длины в фиксированные моменты времени  
**Дополнительные механизмы:** буферизация трафика, генерация фиктивного трафика

---

## 1. Постановка задачи

Разработать стенд, имитирующий информационное взаимодействие двух пользователей (П1 и П2) по легитимному каналу связи, контролируемому устройством защиты (УЗ). В ПК Пользователя 1 внедрена закладка, реализующая скрытый канал передачи информации на основе изменения длин передаваемых пакетов (Пример 5). Злоумышленник (П2) прослушивает легитимный канал и извлекает скрытое сообщение.

Устройство защиты работает в **пассивном режиме** — пересылает трафик без модификации.

---

## 2. Теоретические основы

### 2.1. Скрытый канал (Пример 5)

Пусть \( L \) — максимальная длина пакета (в байтах), \( n \) — параметр скрытого канала, причём \( n \mid L \).

Отрезок \([1, L]\) разбивается на \(\frac{L}{n}\) диапазонов. Алфавит закладки состоит из \(\frac{L}{n}\) символов.

Для передачи символа с номером \( i \) (\( i = 1, \ldots, \frac{L}{n} \)) отправляется пакет длиной \( l \), удовлетворяющей неравенству:

$$(i - 1) \cdot n < l \leq i \cdot n$$

**Кодирование:** байт сообщения \( b \in [0, 255] \) отображается в символ \( i = b + 1 \). Длина пакета выбирается случайно из диапазона \(((i-1) \cdot n + 1, \; i \cdot n]\).

**Декодирование:** по длине пакета \( l \) вычисляется символ \( i = \lceil l / n \rceil \), затем байт \( b = i - 1 \).

При значениях по умолчанию \( L = 1024 \), \( n = 4 \) размер алфавита равен 256, что позволяет кодировать один байт одним пакетом. При других значениях \( n \) (и меньшем алфавите) используется кодирование в соответствующей системе счисления.

### 2.2. Модель 3

Легитимный трафик: пакеты случайной длины передаются в фиксированные моменты времени с интервалом \( T \).

### 2.3. Буферизация трафика

Вместо отправки одного символа за интервал, закладка накапливает группу из \( B \) символов (параметр `--buffer-size`) и отправляет их пакетной серией (burst) с малым межпакетным интервалом.

### 2.4. Генерация фиктивного трафика

Между скрытыми пакетами генерируются фиктивные (dummy) пакеты случайной длины в случайные моменты времени. Это затрудняет обнаружение скрытого канала устройством защиты. Интенсивность фиктивного трафика задаётся параметром `--dummy-rate`.

## 3. Архитектура стенда

### 3.1. Схема

```
 П1 (192.168.56.10)          УЗ (192.168.56.11)          П2 (192.168.56.12)
┌──────────────────┐      ┌──────────────────┐      ┌──────────────────┐
│  sender.py       │─TCP─>│ security_device.py│─TCP─>│  receiver.py     │
│  (отправитель +  │─UDP─>│ (пассивный режим) │─UDP─>│  (получатель /   │
│   закладка)      │      │                  │      │   злоумышленник) │
└──────────────────┘      └──────────────────┘      └──────────────────┘
```

### 3.2. Инфраструктура

- **3 виртуальные машины** Ubuntu 22.04 (Vagrant + VirtualBox)
- **Приватная сеть** 192.168.56.0/24
- **Язык реализации:** Python 3 (стандартная библиотека, без внешних зависимостей)

### 3.3. Протокол взаимодействия

| Канал | Порт | Назначение |
|-------|------|------------|
| TCP   | 9000 | Управление: сигналы START / END с параметрами |
| UDP   | 9001 | Данные: скрытые пакеты + фиктивный трафик |

Порядок работы:

1. П1 устанавливает TCP-соединение с УЗ и отправляет START (параметры: `num_symbols`, `num_bytes`, `L`, `n`, `interval`, `buffer_size`).
2. УЗ ретранслирует TCP-данные на П2.
3. После задержки синхронизации (2 с) П1 начинает отправку UDP-пакетов.
4. Скрытые пакеты идут с фиксированным интервалом \( T \); фиктивные — в случайные моменты.
5. По окончании П1 отправляет END по TCP.
6. П2 декодирует скрытое сообщение по длинам и таймингам пакетов.

## 4. Описание реализации

### 4.1. Структура файлов

```
Vagrantfile                — конфигурация 3 ВМ (Vagrant + VirtualBox)
scripts/
  common.py                — общие утилиты (кодирование, протокол)
  sender.py                — П1 + закладка
  security_device.py       — УЗ (пассивная пересылка TCP и UDP)
  receiver.py              — П2 / злоумышленник
report.md                  — данный отчёт
```

### 4.2. common.py

Содержит:

- **`encode_symbol(symbol, n, L)`** — выбирает случайную длину пакета для символа.
- **`decode_symbol(length, n)`** — восстанавливает символ по длине пакета.
- **`message_to_symbols(data, alphabet_size)`** — преобразует байты в список символов (при алфавите ≥256 — побайтово, иначе — в соответствующей системе счисления).
- **`symbols_to_message(symbols, alphabet_size, num_bytes)`** — обратное преобразование.
- **`send_control` / `recv_control`** — отправка и приём JSON-сообщений с длиной-префиксом по TCP.

### 4.3. sender.py

Отправитель с закладкой:

1. Принимает секретное сообщение (`-m` текст или `-f` файл).
2. Преобразует его в символы.
3. Устанавливает TCP-соединение с УЗ, отправляет START.
4. После задержки синхронизации начинает отправку по UDP:
   - **Скрытые пакеты** — в фиксированные моменты (каждые `T` секунд), длина кодирует символ.
   - **Буферизация** — при `--buffer-size > 1` за один слот отправляется серия из `B` пакетов.
   - **Фиктивный трафик** — между слотами отправляются пакеты случайной длины в случайные моменты.
5. После всех символов отправляет END по TCP.

### 4.4. security_device.py

Устройство защиты (пассивный режим):

- **TCP:** принимает входящее соединение от П1, устанавливает соединение с П2, ретранслирует все данные.
- **UDP:** принимает датаграммы и пересылает на П2, сохраняя размер пакета.

### 4.5. receiver.py

Получатель / злоумышленник:

1. Запускает фоновый поток `PacketCollector`, который записывает все UDP-пакеты с метками времени.
2. По TCP принимает START (с параметрами) и END.
3. После END останавливает сбор и декодирует:
   - Сортирует пакеты по времени.
   - Для каждого ожидаемого момента (кратного `T`) находит ближайший пакет (бинарный поиск + окно ±10).
   - Фиктивные пакеты автоматически отсеиваются, т.к. их время не совпадает с ожидаемым.
4. Восстанавливает исходное сообщение и выводит / сохраняет в файл.

## 5. Инструкция по запуску

### 5.1. Предварительные требования

- VirtualBox 6.1+ (или 7.x)
- Vagrant 2.3+

> **Примечание для VirtualBox 7.x:** может потребоваться разрешение подсети в файле
> `/etc/vbox/networks.conf` (Linux/macOS) или `%USERPROFILE%\.VirtualBox\networks.conf` (Windows):
> ```
> * 192.168.56.0/24
> ```

### 5.2. Запуск виртуальных машин

```bash
cd hidden-data-transmission
vagrant up
```

### 5.3. Запуск компонентов стенда

Открыть **3 терминала** и подключиться к ВМ:

**Терминал 1 — П2 (получатель, запускается первым):**

```bash
vagrant ssh p2
cd /home/vagrant/scripts
python3 receiver.py
```

**Терминал 2 — УЗ (устройство защиты):**

```bash
vagrant ssh uz
cd /home/vagrant/scripts
python3 security_device.py
```

**Терминал 3 — П1 (отправитель, запускается последним):**

```bash
vagrant ssh p1
cd /home/vagrant/scripts
python3 sender.py -m "Secret message"
```

### 5.4. Параметры sender.py

| Параметр | Описание | По умолчанию |
|---|---|---|
| `-m` / `-f` | Секретное сообщение (текст / файл) | обязательный |
| `--uz-host` | IP-адрес УЗ | 192.168.56.11 |
| `-L` | Макс. длина пакета (байт) | 1024 |
| `-n` | Параметр канала (делитель L) | 4 |
| `-T` | Интервал отправки (сек) | 0.5 |
| `--buffer-size` | Символов в одной серии | 1 |
| `--dummy-rate` | Интенсивность фиктивного трафика | 2.0 |

### 5.5. Параметры receiver.py

| Параметр | Описание | По умолчанию |
|---|---|---|
| `-o` / `--output` | Сохранить декодированное сообщение в файл | — |

### 5.6. Примеры

```bash
# Передача текста с n=8 (алфавит = 128)
python3 sender.py -m "Hello" -n 8

# Передача файла с буферизацией (4 символа за раз)
python3 sender.py -f secret.txt --buffer-size 4

# Увеличение фиктивного трафика
python3 sender.py -m "Test" --dummy-rate 5.0

# Сохранение результата на приёмнике
python3 receiver.py -o decoded.txt
```

## 7. Выводы

Реализован лабораторный стенд, демонстрирующий скрытый канал передачи информации на основе изменения длин пакетов (Пример 5 с параметром \( n \)). Стенд состоит из трёх виртуальных машин: отправителя с закладкой (П1), пассивного устройства защиты (УЗ) и получателя-злоумышленника (П2).

Реализованы требуемые механизмы:

- **Буферизация трафика** — параметр `--buffer-size` позволяет отправлять несколько символов за один временной слот, увеличивая пропускную способность скрытого канала.
- **Генерация фиктивного трафика** — параметр `--dummy-rate` управляет интенсивностью фиктивных пакетов, затрудняющих обнаружение скрытого канала.
- **Параметр n** — задаётся через `-n`, изменяет размер алфавита и гранулярность кодирования.

Скрытый канал корректно передаёт и декодирует произвольные сообщения (текст и бинарные данные) при различных конфигурациях параметров.
