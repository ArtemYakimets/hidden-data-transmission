# Лабораторные работы №1 и №3. Скрытый канал на основе изменения длин пакетов

## Вариант 3 — Пример 5 (с параметром n)

**Модель передачи:** Модель 3 — пакеты случайной длины в фиксированные моменты времени  
**Дополнительные механизмы:** буферизация трафика, генерация фиктивного трафика

---

## 1. Постановка задачи

### Лабораторная работа №1

Разработать стенд, имитирующий информационное взаимодействие двух пользователей (П1 и П2) по легитимному каналу связи, контролируемому устройством защиты (УЗ). В ПК Пользователя 1 внедрена закладка, реализующая скрытый канал передачи информации на основе изменения длин передаваемых пакетов (Пример 5). Злоумышленник (П2) прослушивает легитимный канал и извлекает скрытое сообщение.

Устройство защиты работает в **пассивном режиме** — пересылает трафик без модификации.

### Лабораторная работа №3

Модифицировать стенд так, чтобы устройство с закладкой и устройство защиты являлись двумя логически отдельными устройствами. Средство защиты теперь не является «заглушкой». Реализовать две схемы превентивного противодействия:

1. **Схема 1** — ограничивает пропускную способность скрытого канала.
2. **Схема 2** — полностью устраняет возможность построения скрытого канала.

## 2. Теоретические основы

### 2.1. Скрытый канал (Пример 5)

Пусть \( L \) — максимальная длина пакета (в байтах), \( n \) — параметр скрытого канала, причём \( n \mid L \).

Отрезок \([1, L]\) разбивается на \(\frac{L}{n}\) диапазонов. Алфавит закладки состоит из \(\frac{L}{n}\) символов.

Для передачи символа с номером \( i \) (\( i = 1, \ldots, \frac{L}{n} \)) отправляется пакет длиной \( l \), удовлетворяющей неравенству:

$$(i - 1) \cdot n < l \leq i \cdot n$$

**Кодирование:** байт сообщения \( b \in [0, 255] \) отображается в символ \( i = b + 1 \). Длина пакета выбирается случайно из диапазона \(((i-1) \cdot n + 1, \; i \cdot n]\).

**Декодирование:** по длине пакета \( l \) вычисляется символ \( i = \lceil l / n \rceil \), затем байт \( b = i - 1 \).

При значениях по умолчанию \( L = 1024 \), \( n = 4 \) размер алфавита равен 256, что позволяет кодировать один байт одним пакетом.

### 2.2. Модель 3

Легитимный трафик: пакеты случайной длины передаются в фиксированные моменты времени с интервалом \( T \).

### 2.3. Буферизация трафика

Вместо отправки одного символа за интервал, закладка накапливает группу из \( B \) символов (параметр `--buffer-size`) и отправляет их пакетной серией (burst) с малым межпакетным интервалом.

### 2.4. Генерация фиктивного трафика

После отправки скрытых пакетов генерируются фиктивные (dummy) пакеты случайной длины. Интенсивность задаётся параметром `--dummy-rate`.

### 2.5. Схемы противодействия (ЛР3)

**Схема 1 — нормализация длин пакетов (normalize, k):**

Устройство защиты округляет длину каждого UDP-пакета до ближайшего кратного \( k \) (дополняя случайными байтами). Это снижает размер эффективного алфавита с \( L/n \) до \( L/k \).

- Пропускная способность скрытого канала: \( \log_2(L/k) \) бит/пакет вместо \( \log_2(L/n) \).
- При \( L = 1024, n = 4, k = 32 \): алфавит падает с 256 до 32 символов, пропускная способность — с 8 до 5 бит/пакет.

**Схема 2 — дополнение до фиксированной длины (pad, L):**

Устройство защиты дополняет каждый UDP-пакет до длины \( L \). Все пакеты становятся одинаковой длины, информация в длинах пакетов полностью уничтожается.

- Пропускная способность скрытого канала: 0 бит/пакет.

## 3. Архитектура стенда

### 3.1. Схема

```
 П1 (192.168.56.10)          УЗ (192.168.56.11)          П2 (192.168.56.12)
┌──────────────────┐      ┌──────────────────┐      ┌──────────────────┐
│  sender.py       │─TCP─>│ security_device.py│─TCP─>│  receiver.py     │
│  (отправитель +  │─UDP─>│  (passive /       │─UDP─>│  (получатель /   │
│   закладка)      │      │   normalize / pad)│      │   злоумышленник) │
└──────────────────┘      └──────────────────┘      └──────────────────┘
```

### 3.2. Инфраструктура

- **3 виртуальные машины** Ubuntu 22.04 (Vagrant + VirtualBox)
- **Приватная сеть** 192.168.56.0/24
- **Язык реализации:** Python 3 (стандартная библиотека, без внешних зависимостей)

### 3.3. Протокол взаимодействия

| Канал | Порт | Назначение |
|-------|------|------------|
| TCP   | 9000 | Управление: сигналы START / END с параметрами |
| UDP   | 9001 | Данные: скрытые пакеты + фиктивный трафик |

Порядок работы:

1. П1 устанавливает TCP-соединение с УЗ и отправляет START с параметрами.
2. УЗ ретранслирует TCP-данные на П2.
3. После задержки синхронизации (2 с) П1 отправляет скрытые пакеты с фиксированным интервалом \( T \).
4. После скрытых пакетов отправляется фиктивный трафик.
5. По окончании П1 отправляет END по TCP.
6. П2 декодирует первые \( N \) пакетов (по времени прибытия) — это скрытые пакеты.

## 4. Описание реализации

### 4.1. Структура файлов

```
Vagrantfile                — конфигурация 3 ВМ (Vagrant + VirtualBox)
scripts/
  common.py                — общие утилиты (кодирование, протокол)
  sender.py                — П1 + закладка
  security_device.py       — УЗ (passive / normalize / pad)
  receiver.py              — П2 / злоумышленник
  start_daemon.py          — вспомогательный демонизатор процессов
run.bat / run.sh           — запуск ВМ
run_lab1.bat / run_lab1.sh — демонстрация ЛР1
run_lab3.bat / run_lab3.sh — демонстрация ЛР3
report.md                  — данный отчёт
```

### 4.2. common.py

- **`encode_symbol(symbol, n, L)`** — выбирает случайную длину пакета для символа.
- **`decode_symbol(length, n)`** — восстанавливает символ по длине пакета.
- **`message_to_symbols` / `symbols_to_message`** — преобразование сообщения ↔ символы.
- **`send_control` / `recv_control`** — JSON-сообщения с длиной-префиксом по TCP.

### 4.3. sender.py

1. Принимает секретное сообщение (`-m` текст или `-f` файл).
2. Отправляет скрытые пакеты с фиксированным интервалом (Model 3).
3. После всех скрытых пакетов отправляет фиктивный трафик (`--dummy-rate`).
4. При `--buffer-size > 1` за один слот отправляется серия пакетов.

### 4.4. security_device.py

Режимы работы (`--mode`):

| Режим | Описание |
|-------|----------|
| `passive` | Пересылает без изменений (ЛР1) |
| `normalize` | Округляет длину до кратного `--k` (ЛР3, схема 1) |
| `pad` | Дополняет до `--max-len` (ЛР3, схема 2) |

При получении SIGTERM выводит статистику: количество пакетов, исходные/модифицированные байты, overhead.

### 4.5. receiver.py

1. Собирает UDP-пакеты в фоновом потоке.
2. После END сортирует пакеты по времени и берёт первые \( N \) — это скрытые пакеты.
3. Декодирует длины в символы и восстанавливает сообщение.

## 5. Инструкция по запуску

### 5.1. Предварительные требования

- VirtualBox 6.1+ (или 7.x)
- Vagrant 2.3+

### 5.2. Быстрый запуск

```bash
# 1. Развернуть ВМ (один раз)
run.bat                    # Windows
./run.sh                   # Linux/macOS

# 2. Демонстрация ЛР1
run_lab1.bat               # Windows
./run_lab1.sh              # Linux/macOS

# 3. Демонстрация ЛР3 (можно сразу после ЛР1, без перезапуска ВМ)
run_lab3.bat               # Windows
./run_lab3.sh              # Linux/macOS
```

### 5.3. Ручной запуск (3 терминала)

**П2 (первым):**

```bash
vagrant ssh p2 -c "cd /home/vagrant/scripts && python3 receiver.py"
```

**УЗ:**

```bash
vagrant ssh uz -c "cd /home/vagrant/scripts && python3 security_device.py --mode passive"
# Или для ЛР3:
vagrant ssh uz -c "cd /home/vagrant/scripts && python3 security_device.py --mode normalize --k 32"
vagrant ssh uz -c "cd /home/vagrant/scripts && python3 security_device.py --mode pad --max-len 1024"
```

**П1 (последним):**

```bash
vagrant ssh p1 -c "cd /home/vagrant/scripts && python3 sender.py -m 'Secret message'"
```

### 5.4. Параметры

**sender.py:**

| Параметр | Описание | По умолчанию |
|---|---|---|
| `-m` / `-f` | Секретное сообщение (текст / файл) | обязательный |
| `-L` | Макс. длина пакета (байт) | 1024 |
| `-n` | Параметр канала (делитель L) | 4 |
| `-T` | Интервал отправки (сек) | 0.5 |
| `--buffer-size` | Символов в одной серии | 1 |
| `--dummy-rate` | Фиктивных пакетов на 1 скрытый | 2.0 |

**security_device.py:**

| Параметр | Описание | По умолчанию |
|---|---|---|
| `--mode` | Режим: passive / normalize / pad | passive |
| `--k` | Шаг нормализации (режим normalize) | 32 |
| `--max-len` | Фиксированная длина (режим pad) | 1024 |

Сообщение: «Hello from covert channel» (25 байт).

**Отправитель:**

**Получатель:**

```

```

**Результат:** сообщение передано и декодировано **корректно**.

### 6.2. ЛР3 — Схема 1: Нормализация (k=32)

Устройство защиты округляет длины пакетов до кратного 32.

**Получатель:**

```
[P2] Decoded bytes (hex): 4f676f6f6f2767776f6f27676f7767777727676f676f6f676f
[P2] Decoded message: Ogooo'gwoo'gowgww'gogoogo
```

**Статистика УЗ:**

```
[UZ] Mode: normalize
[UZ] Packets forwarded: 75
[UZ] Bytes original: 38266
[UZ] Bytes after modification: 39328
[UZ] Overhead: 2.8%
[UZ] Normalization step k=32
```

**Анализ:**

| Метрика | Без защиты | С нормализацией (k=32) |
|---------|-----------|----------------------|
| Алфавит скрытого канала | 256 (L/n) | 32 (L/k) |
| Пропускная способность | 8 бит/пакет | 5 бит/пакет |
| Сообщение декодировано | Корректно | Искажено |
| Overhead основного канала | 0% | 2.8% |

Нормализация снижает эффективный алфавит в 8 раз (k/n = 32/4 = 8). Каждые 8 смежных символов отображаются в один, что приводит к существенному искажению декодируемого сообщения. Влияние на основной канал минимально (2.8% overhead).

### 6.3. ЛР3 — Схема 2: Дополнение до фиксированной длины (L=1024)

Устройство защиты дополняет все пакеты до 1024 байт.

**Получатель:**

```
[P2] Decoded bytes (hex): ffffffffffffffffffffffffffffffffffffffffffffffffff
[P2] Cannot decode as UTF-8 (25 bytes)
```

**Статистика УЗ:**

```
[UZ] Mode: pad
[UZ] Packets forwarded: 75
[UZ] Bytes original: 33671
[UZ] Bytes after modification: 76800
[UZ] Overhead: 128.1%
[UZ] Fixed length L=1024
```

**Анализ:**

| Метрика | Без защиты | С дополнением (L=1024) |
|---------|-----------|----------------------|
| Алфавит скрытого канала | 256 | 1 |
| Пропускная способность | 8 бит/пакет | 0 бит/пакет |
| Сообщение декодировано | Корректно | Полностью уничтожено |
| Overhead основного канала | 0% | 128.1% |

Все пакеты стали одинаковой длины 1024 байта. Каждый символ декодируется как 255 (0xFF). Скрытый канал **полностью устранён**. Однако overhead основного канала составляет ~128%, что существенно увеличивает объём передаваемых данных.

## 7. Выводы

### ЛР1

Реализован лабораторный стенд, демонстрирующий скрытый канал передачи информации на основе изменения длин пакетов (Пример 5 с параметром \( n \)). Стенд корректно передаёт и декодирует произвольные сообщения. Реализованы буферизация трафика и генерация фиктивного трафика.

### ЛР3

Стенд модифицирован: устройство защиты и закладка — логически отдельные устройства. Реализованы две схемы противодействия:

**Схема 1 (нормализация)** — ограничивает пропускную способность скрытого канала, снижая размер алфавита. При k=32 пропускная способность падает на 37.5% (с 8 до 5 бит/пакет), а сообщения искажаются. Влияние на основной канал минимально (~3% overhead). Схема применима в реальных условиях, когда необходимо снизить угрозу утечки без существенного влияния на легитимный трафик.

**Схема 2 (дополнение)** — полностью устраняет скрытый канал, приводя все пакеты к одинаковой длине. Пропускная способность скрытого канала равна нулю. Однако overhead основного канала составляет ~128%, что делает схему применимой только в критически важных сценариях, где защита от утечки важнее эффективности использования канала связи.

Обе схемы эффективны для защиты от скрытых каналов, основанных на длинах пакетов. Выбор схемы зависит от требований: нормализация — для баланса между защитой и производительностью, дополнение — для полного устранения канала.
