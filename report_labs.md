# План рассказа по лабораторным работам №1 и №3

Вариант 7. Модель 2, Пример 8. Скрытый канал по межпакетным интервалам.

## 1. Общая схема: как всё устроено

### 1.1. Роли узлов

| Узел | ВМ (IP) | Роль |
|------|---------|------|
| **П1** | `p1`, 192.168.56.10 | Легитимный пользователь + **закладка** (`sender.py`) |
| **УЗ** | `uz`, 192.168.56.11 | **Устройство защиты** (`security_device.py`) |
| **П2** | `p2`, 192.168.56.12 | Легитимный получатель + **злоумышленник** (`receiver.py`) |

### 1.2. Два канала связи

```text
                    TCP :9000 (управление)
  П1 ──────────────────► УЗ ──────────────────► П2
       JSON: START / END       прозрачная ретрансляция

                    UDP :9001 (данные)
  П1 ──────────────────► УЗ ──────────────────► П2
       пакеты 512 байт       ЛР1: без задержек
       с кодированными       ЛР3: джиттер / регулирование
       интервалами
```

- **TCP** передаёт параметры: число бит, t_short, t_long, threshold, buffer_size.
- **UDP** несёт пакеты **фиксированной длины** (512 байт, модель 2). Скрытая информация закодирована **во временных интервалах** между пакетами (пример 8).

### 1.3. Идея скрытого канала (пример 8)

- Два интервала: `t_short = 50 мс` (бит 0) и `t_long = 150 мс` (бит 1).
- Порог декодера: `θ = 100 мс`. Если Δt < θ → 0, иначе → 1.
- Добавляется случайный джиттер ±20 мс для маскировки.
- Пропускная способность ≈ 10 бит/с (1.25 байт/с).

### 1.4. Временная последовательность

```text
  П1                    УЗ                    П2
   │                     │                     │
   │──── TCP START ─────►│────────────────────►│  параметры сеанса
   │  sleep 2s           │                     │
   │──── UDP sync pkt ──►│────────────────────►│  начало отсчёта
   │   [50ms]            │                     │
   │──── UDP pkt ───────►│────────────────────►│  Δt=50ms → бит 0
   │   [150ms]           │                     │
   │──── UDP pkt ───────►│────────────────────►│  Δt=150ms → бит 1
   │   ...               │                     │
   │  (burst pause + separator pkt каждые 8 бит)
   │──── dummy pkts ────►│────────────────────►│  случайные интервалы
   │──── TCP END ───────►│────────────────────►│  декодирование
```

### 1.5. Запуск

1. `run.bat` / `./run.sh` — поднять ВМ.
2. `run_lab1.bat` / `./run_lab1.sh` — ЛР1 (passive).
3. `run_lab3.bat` / `./run_lab3.sh` — ЛР3 (jitter + regulate).

## 2. План рассказа: Лабораторная работа №1

### 2.1. Вступление

- Канал по времени: информация не в содержимом и не в длине пакета, а **в паузах между пакетами**.
- Модель 2: длина фиксированная → нельзя обнаружить по статистике длин.
- УЗ в ЛР1 — пассивная пересылка, задержки не вносит.

### 2.2. Разбор ключевого кода

#### `common.py` — битовая арифметика

| Функция | Назначение |
|---------|------------|
| `message_to_bits(data)` | Байты → список бит (MSB first). 25 байт → 200 бит. |
| `bits_to_message(bits, n)` | Обратно: биты → байты. |
| `send_control` / `recv_control` | 4 байта длины + JSON по TCP. |

#### `sender.py` — П1 + закладка

| Блок | Комментарий |
|------|-------------|
| `parse_args()` | `-m`/`-f`, `--pkt-size`, `--t-short`, `--t-long`, `--jitter`, `--buffer-size`, `--dummy-count`. |
| TCP retry (15 попыток) | Устройство защиты может быть ещё не готово. |
| `send_control(START)` | Передаёт num_bits, t_short, t_long, threshold, buffer_size. |
| Sync packet | Первый UDP-пакет — точка отсчёта интервалов. |
| Цикл `while idx < total_bits` | Для бита 0 ждём ~50 мс, для 1 — ~150 мс (+ джиттер ±20 мс). Каждые `buffer_size` бит — пауза 300 мс + разделительный пакет. |
| Фаза dummy | 20 пакетов со случайными интервалами 20–200 мс. |

#### `security_device.py` — passive

| Функция | Комментарий |
|---------|-------------|
| `udp_forward_passive` | `recvfrom` → `sendto`, без задержки. Интервалы сохраняются. |
| `tcp_forward` | Байтовая ретрансляция TCP. |

#### `receiver.py` — П2

| Класс / функция | Комментарий |
|-----------------|-------------|
| `PacketCollector` | Фоновый поток: `timestamps.append(time.time())` для каждой датаграммы. |
| `decode_timing` | Сортировка по времени → вычисление Δt → сравнение с θ. Разделительные интервалы (между burst'ами) пропускаются. |
| `bits_to_message` | 200 бит → 25 байт. |

### 2.3. Что показать в выводе

**П1:**
```
[P1] Packet size: 512 bytes (fixed)
[P1] T_short=0.05s  T_long=0.15s  jitter=±0.02s  buffer=8
[P1] Message: 25 bytes -> 200 bits
[P1] START sent, syncing 2.0s ...
[P1] Sync packet sent
[P1] Sent 200/200 bits
[P1] Sending 20 dummy packets ...
[P1] Done — 200 covert bits + 20 dummy packets sent
```

**П2:**
```
[P2] START — 200 bits, pkt=512B, T0=0.05s, T1=0.15s, thr=0.1s, buf=8
[P2] END received, decoding ...
[P2] Packets received: 245 total
[P2] Covert: 201 pkts (200 intervals = bits)
[P2] Dummy: 44 pkts
[P2] Avg covert interval: 99.8 ms
[P2] Decoded bytes (hex): 48656c6c6f2066726f6d20636f76657274206368616e6e656c
[P2] Decoded message: Hello from covert channel
```

**Комментарии:** 200 бит декодированы без ошибок. Hex = UTF-8 оригинала. Средний интервал ~100 мс = (50+150)/2.

### 2.4. Возможные вопросы

- **Почему dummy не мешают?** — Они идут *после* скрытых; берём первые N интервалов.
- **Что за burst pause?** — Каждые 8 бит вставляется 300 мс пауза + разделительный пакет, декодер пропускает этот интервал.
- **Почему модель 2?** — Фиксированная длина исключает канал по длине; информация только во времени.

## 3. План рассказа: Лабораторная работа №3

### 3.1. Вступление

- УЗ теперь **активно** модифицирует трафик.
- Две схемы:
  1. **Джиттер** — случайная задержка каждого пакета → ограничение пропускной способности СК.
  2. **Регулирование** — фиксированный интервал между пакетами → полное устранение СК.

### 3.2. Разбор кода

#### `security_device.py` — активные режимы

| Режим | Реализация | Эффект |
|-------|------------|--------|
| `jitter` | `delay = abs(gauss(0, σ))`, пересылка в отдельном потоке через `delay` секунд | Интервалы зашумлены → часть бит инвертируется |
| `regulate` | `queue.Queue()`, приём в фоне, пересылка через `time.sleep(T_fix)` | Все интервалы = `T_fix` → канал уничтожен |
| `_summary` (SIGTERM) | Печатает число пакетов, средний джиттер или фиксированный интервал | Статистика для отчёта |

### 3.3. Что показать в выводе

**Схема 1 — Джиттер (σ = 60 мс):**

П2:
```
[P2] Decoded message: HeLlo"from ├│overt channel
```

УЗ:
```
[UZ] === SUMMARY ===
[UZ] Mode: jitter
[UZ] Packets forwarded: 245
[UZ] Max jitter setting: 60 ms
[UZ] Avg actual jitter: 47.2 ms
```

**Комментарий:** сообщение искажено — ~12 бит из 200 инвертированы. Канал ограничен, но не устранён.

**Схема 2 — Регулирование (T_fix = 100 мс):**

П2:
```
[P2] Decoded bytes (hex): ffffffffffff...ff
[P2] Cannot decode as UTF-8 (25 bytes)
```

УЗ:
```
[UZ] === SUMMARY ===
[UZ] Mode: regulate
[UZ] Packets forwarded: 245
[UZ] Fixed interval: 100 ms
[UZ] All inter-packet intervals normalized to 100 ms
```

**Комментарий:** все Δt = 100 мс ≥ θ → все биты = 1 → 0xFF. Канал **полностью устранён**.

### 3.4. Сводная таблица

| | ЛР1 (passive) | ЛР3 jitter | ЛР3 regulate |
|---|---------------|------------|--------------|
| Скрытый канал | Работает (0% ошибок) | Ограничен (~6% BER) | Устранён (100% ошибок) |
| C_eff | 10 бит/с | ~1.3 бит/с | 0 бит/с |
| Влияние на основной канал | Нет | Задержка ~50 мс | Ограничение скорости |

### 3.5. Вывод для защиты

- **Jitter** — компромисс: минимальное влияние на основной канал, но канал только ослаблен.
- **Regulate** — полная защита, ценой ограничения скорости пересылки.
- Для канала по времени регулирование эффективнее, чем для канала по памяти, поскольку уничтожает именно тот параметр (интервал), который несёт информацию.
